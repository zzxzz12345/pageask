# 逐页优先发布与跳页抢占

验证日期：2026-10-19。内容原则仍为grounded-sparse-v5，已有合格缓存继续复用；交付流程为progressive-v1。

## 发布顺序

一批仍同时提供最多十页提取文字与逐页整页原图，供模型理解上下文。发布权限按阶段冻结：第一次只能提交最前面的未完成页；后续每次最多两页，且必须包含当前最前面的未完成页。同一条模型回复即使连续调用多个工具，也不能绕过本轮允许页。

模型唯一发布入口是submit_reading_batch。新知识草稿与批注一起提交，内部完成知识复用、精确原文定位、题目与覆盖率校验。每页独立保存并产生page_ready事件，不等待下一页；后面页校验失败不撤回前面结果。

## 提交后自动显示

页面结果和事件游标在同一SQLite事务提交。提交后唤醒SSE订阅者并发送完整页面结果，ai-reader.js直接更新缓存和划线层，状态及知识数量随后同步。连接中断后EventSource自动重连，使用Last-Event-ID重放遗漏事件；连接不可用时以轮询兜底。原文渲染和手动划线始终独立。

这个机制消除了“整批结束才显示”和“必须刷新才显示”的等待。它不消除模型阅读、生成与网关响应本身的耗时。

## 跳页抢占

目录、输入页码、知识出处等显式跳转，以及与上一页码不连续的移动，立即撤销旧任务的写入权限、释放其页面占用，并从最新位置建立新的十页窗口；即使新位置仍在旧窗口中也要重建。上一页/下一页正常逐页阅读继续使用每五页补充五页的机制。新位置已缓存时直接复用。

调度器取消正在等待的模型调用，立刻处理新位置。每个写事务核查任务状态，旧工具线程、模型迟到响应、完成回调都不能保存或恢复旧任务。已完成批注和知识保留，superseded任务重启后不会复活。远程提供商是否停止已经接收的推理不由本地程序控制。

前端在点击导航时发送进度，不等PDF渲染结束。阅读会话带递增请求序号，旧点击请求即使因网络延迟晚于新点击到达也会被忽略；旧页的状态响应也不能覆盖新页显示。

## 自动化及浏览器验证

30项测试通过，包含原有原文约束、知识复用、10/5预取，以及以下交付场景：

- 真实HTTP SSE在模型任务仍运行、后续页仍等待时收到第一页完整选择题，断线后只补收游标之后的页。
- 第一次混交多页、同轮越序提交、跳过最前页会被拒绝；后续页失败仍保留已接受页面。
- 运行中的模型等待收到取消，最新页任务开始；即使旧任务延迟退出，新位置也能先运行，旧保存被拒绝。
- 同窗口跳页、显式相邻跳页、快速点击乱序、切书、取消后重启均符合抢占规则。
- 无思考请求实际走Responses，使用reasoning.effort=none；通过HTTP模拟传输核对真实请求正文、工具调用解析和完整工具历史回传，不依赖服务端会话。

浏览器受控验证使用本书原始PDF和实际LangChain发布工具，未调用真实模型生成内容：

1. 阻断所有状态轮询，将后续页暂停。第一页工具提交后约327毫秒出现划线与三个选项，后台仍运行；页面导航记录为1，没有刷新或脚本报错。该数字只表示工具提交到渲染的链路，不是模型首答耗时。
2. 从55页跳到110页，再跳到130页。后端启动顺序为55、110、130，前两项均收到取消；旧任务标为superseded，仅新130页任务运行。55页已完成批注保留，130页提交后自动显示；无刷新、无页面报错。

受控服务只在测试端口运行，测试结束关闭；生产API没有这些释放开关。
